Final Project: CareTrace

A consequence-aware Neurosymbolic AI agent for trustworthy after-hours pediatric triage.

Scenario (one sentence): An after-hours caregiver consults the agent about a sick child and needs an evidence-backed overnight plan plus explicit escalation criteria (urgent care vs ER).

Overview

We will build a working Neurosymbolic AI agent that supports after-hours pediatric triage by producing a safe, actionable plan a caregiver can follow tonight, along with clear thresholds for when escalation is necessary.

Our focus is not on producing fluent conversation alone. We will engineer trust as a system property: authoritative knowledge, explicit practice logic, calibrated context, and a verifiable rationale that a caregiver can act upon.

Medicine is our flagship domain because authority, protocols, and safety-netting are explicit. The same architectural principles apply in any high-stakes domain (compliance, finance, safety, operations, security).

Project Goals

  • We will translate caregiver language into structured case facts and canonical clinical meaning (SNOMED-backed concepts where appropriate).
  • We will encode a scoped triage protocol as executable logic: required questions, escalation triggers, and exceptions.
  • We will enforce hard safety constraints (e.g., “must-not-do” recommendations under specific conditions) and produce a decision trace.
  • We will incorporate local context (via a provided or synthetic surveillance feed) as explicitly labeled priors, never as certainty.
  • We will produce concise, decision-oriented output that avoids information overload and supports safe action at night.

Trust via Authority

A core theme of the project is that caregivers need information they can act on and trust. We will operationalize three distinct sources of authority:

  • Authoritative medical knowledge: canonical concepts and decision-relevant facts (e.g., symptom meaning, contraindications, dosing constraints tied to formulation + weight).
  • Practice guidance: a scoped guideline-like decision procedure (what clinicians do) expressed as executable rules: must-ask checks, escalation triggers, and exceptions.
  • Judgment context: a local “what’s going around” style signal represented as priors, used to prioritize questions and frame likelihoods—explicitly labeled as context.

Key design principle: context can inform expectations, but it must never override hard safety gates.

Multi-Agent Architecture (Conceptual)

We will implement the system as a stateful workflow in which specialized components cooperate:

  • Interpretation Agent (LLM): extracts structured fields and drives targeted follow-up questions when protocol-required information is missing.
  • Knowledge Retrieval Agent (KG): queries the team’s Neo4j clinical graph to canonicalize meaning, traverse hierarchy (IS_A), and return a minimal evidence bundle.
  • Safety Logic Agent (Symbolic): executes rules deterministically (obligations, contraindication gates, escalation triggers) and emits a decision trace.
  • Authority Agent (Medication / Reference Knowledge): computes exact recommendations only when required inputs are present, tied to a named reference artifact.
  • Context Agent: injects local priors from the surveillance feed as labeled context, never as asserted fact.
  • Explanation Agent: produces a concise caregiver-facing summary: tonight plan, go-now thresholds, and a trace-backed rationale.
  • Orchestration: enforces a disciplined interaction flow (screen red flags → stabilize → dose (if allowed) → safety-net plan), preventing information bombardment.

Technical Stack

  • Python for integration, orchestration glue, and data handling
  • LLM API (state-of-the-art model) for interpretation, follow-up question generation, and explanation drafting
  • LangGraph for stateful agent workflow orchestration
  • Neo4j AuraDB for the mini clinical knowledge graph
  • PyDatalog for executable rules, constraints, and decision traces
  • Snowstorm / FHIR terminology endpoints for public SNOMED concept discovery and labeling during KG curation
  • Authority artifacts (team-built): a small dosing/contraindication reference and a small local context feed

Scope (Bounded, Implementable, Testable)

To keep the project realistic and implementable, we will work in a bounded context. Each team will choose one presenting complaint cluster and implement:

  • Bounded clinical substrate: a limited SNOMED-backed mini-KG relevant to the chosen complaint.
  • Bounded protocol: a small set of rules (must-ask checks, escalation triggers, contraindication gates).
  • Bounded context priors: a small surveillance-style feed used as labeled context.
  • Bounded output: a short decisional plan (not a long differential).

Baseline Comparison

We will compare our Neurosymbolic AI agent against a state-of-the-art LLM conversation baseline (and, where appropriate, a simple retrieval-augmented baseline). The goal is to demonstrate where pure conversation can be confusing or falsely authoritative (especially around “local context” and “what guidelines say”), and how an explicit neurosymbolic pipeline delivers disciplined decisions with a verifiable authority chain and reproducible traces.

High-Level Deliverables

  • A mini clinical knowledge graph running in Neo4j AuraDB (scoped slice, queryable, documented).
  • An executable triage protocol implemented as rules plus a decision trace format.
  • A small authoritative dosing/contraindication reference and a local context feed (synthetic or provided).
  • An end-to-end demo: dialogue → structured facts → KG retrieval → rule decision → response with provenance.
  • A small baseline comparison showing where baselines drift vs where the NeSy agent remains disciplined and auditable.
